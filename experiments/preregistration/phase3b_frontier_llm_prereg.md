## 1. Study Objective & Context

Phase 3 evaluated hypothesis generation from a local LLM ($Llama3\text{-}8B$) and found **no detectable advantage over random generation** (Mann-Whitney $p = 0.69$). An informal pilot using a frontier model produced $68/150$ in-sample survivors (vs random's $6/150$), an all-hypothesis mean OOS edge of $+0.194$ (vs $+0.027$), and $0/21$ direction survivors (confirming *direction-is-dead*).

However, the pilot exposed a gate-design flaw: comparing survivor pools penalizes high-survival arms by introducing survivor selection bias.

**Phase 3b** is the formal pre-registered study testing whether a naive frontier LLM (Claude via API, zero program context) generates out-of-sample trading edge statistically superior to random grammar synthesis ($R_{\text{FRESH}}$) and textbook technical folklore ($TEXTBOOK$), evaluated across full hypothesis distributions without survivor selection bias.

---

## 2. Experimental Arms (N=150 per Arm)

1. **`F-NAIVE` (Primary Treatment Arm)**:
   - Generated by a frontier LLM (Claude via API, model string recorded) using ONLY the naive prompt ([`data/hypotheses/phase3b/phase3b_naive_prompt.txt`](../../data/hypotheses/phase3b/phase3b_naive_prompt.txt)).
   - Strict zero-context requirement: NO information about prior program results, no dataset statistics, no hints about target predictability.
   - Raw API response log committed as `data/hypotheses/phase3b/f_naive_generation_log.json`.

2. **`F-CONTEXT` (Secondary Arm)**:
   - Existing committed pilot arm (`claude_arm.json`) copied unchanged to `data/hypotheses/phase3b/f_context.json`.
   - Measures the contamination / context premium relative to `F-NAIVE`. (Not gating).

3. **`R-FRESH` (Primary Control Arm)**:
   - 150 new random hypotheses synthesized from grammar $G$ with seed 43 $\rightarrow$ `data/hypotheses/phase3b/r_fresh.json`.

4. **`TEXTBOOK` (Exploratory Arm)**:
   - ~150 hypotheses transcribed mechanically from standard technical/volatility folklore rules (momentum, mean reversion, volume confirmation, VIX rules) using rule templates without LLMs $\rightarrow$ `data/hypotheses/phase3b/textbook.json`.

## 3. Deduplication & Behavioral Clustering

Deduplication occurs strictly in two steps before evaluation results exist:
1. **Structural AST Deduplication**: Exact matching key on compiled predicate syntax.
2. **Behavioral Trigger Clustering**:
   - For all compiled hypotheses, compute the set of in-sample trigger days $T_h$.
   - Compute pairwise Jaccard similarity between hypotheses $A$ and $B$:
     $$J(A, B) = \frac{|T_A \cap T_B|}{|T_A \cup T_B|}$$
   - Any two hypotheses with $J(A, B) > 0.80$ on in-sample trigger days are assigned to the same behavioral cluster using single-linkage connected components.
   - Cluster memberships are computed and frozen prior to out-of-sample edge calculation.

---

## 4. Pre-Registered Statistical Gates & Verdict Rules

### Primary Gate **G-P3B** (Decides headline study verdict)
- **Test**: One-sided Mann-Whitney U test comparing the full distribution of out-of-sample edges ($E_{\text{OOS}}$) across all $N=150$ triggered hypotheses between `F-NAIVE` and `R-FRESH` ($\alpha = 0.05$).
- **Verdict Rule**:
  - If $p < 0.05 \text{ and } \text{Mean}(E_{\text{OOS, F-NAIVE}}) > \text{Mean}(E_{\text{OOS, R-FRESH}}) \rightarrow$ **`FRONTIER-LLM-EDGE`**
  - Otherwise $\rightarrow$ **`NO-FRONTIER-EDGE`**

### Co-Primary Gate **G-P3B-CLUSTER** (Robustness Gate)
- **Test**: Same one-sided Mann-Whitney U test at the cluster level (one value per cluster: mean $E_{\text{OOS}}$ of cluster members).
- **Verdict Rule**:
  - Both **G-P3B** and **G-P3B-CLUSTER** must pass for headline verdict **`FRONTIER-LLM-EDGE`**.
  - If G-P3B and G-P3B-CLUSTER disagree $\rightarrow$ Verdict **`INCONCLUSIVE - CLUSTERING SENSITIVE`**.

## 5. Pre-Registered Falsifiable Predictions

Written before any Phase 3b evaluation data exists:
- **P3B-1**: `F-NAIVE` in-sample survival rate ($p < 0.10$) lands between **12% and 40%** (below contaminated $45.3\%$, above Llama3 $6.7\%$ and random $\approx 4\%$).
- **P3B-2**: Gate **G-P3B** passes ($p < 0.05$, full-distribution OOS edge `F-NAIVE` > `R-FRESH`).
- **P3B-3**: `F-NAIVE` direction-target survivors $\le 2$ (confirming direction is dead).
- **P3B-4**: `F-CONTEXT` survival rate $\ge$ `F-NAIVE` survival rate (context premium $\ge 0$).
- **P3B-5**: `TEXTBOOK` all-hypothesis mean OOS edge lands between `R-FRESH` and `F-NAIVE`.

## 6. Verbatim Naive Prompt Text

```text
You are an expert quantitative researcher analyzing Indian large-cap daily equity and market data.
Your goal is to propose diverse, well-reasoned trading and volatility hypotheses using a strict domain grammar.

## Feature Whitelist (9 Daily Features)
You must use ONLY these 9 feature names in your hypothesis predicates:
1. `close`: Stock or index daily closing price.
2. `volume`: Daily trading volume (shares traded).
3. `delivery_pct`: Delivery volume as a percentage of total volume (higher indicates institutional delivery accumulation).
4. `fii_net_amt`: Foreign Institutional Investor net buying/selling amount in INR crores.
5. `dii_net_amt`: Domestic Institutional Investor net buying/selling amount in INR crores.
6. `adv_dec_ratio`: Market breadth advance-decline ratio (advancing stocks divided by declining stocks).
7. `vix_close`: India VIX index closing level (implied volatility of NIFTY 50 options).
8. `vix_change_5d`: 5-day absolute change in India VIX index level.
9. `vix_vs_20d_ma`: Ratio of current India VIX level to its 20-day moving average (VIX regime indicator).

## Allowed Operators
- Comparisons: `>`, `<`, `>=`, `<=`
- Logical Combinators: `AND`, `OR`

## Allowed Quantile / Percentile Thresholds
All numeric feature threshold values MUST be specified as quantile ranks between 0.20 and 0.80:
`[0.20, 0.25, 0.30, 0.35, 0.40, 0.45, 0.50, 0.55, 0.60, 0.65, 0.70, 0.75, 0.80]`

## Target Modes (Choose Exactly One per Hypothesis)
1. `volatility_5d`: Predicting 5-day forward realized volatility expansion.
2. `vol_regime_expansion`: Predicting a major volatility regime transition (India VIX spike).
3. `direction_3d`: Predicting 3-day forward directional price movement (upward return).

## Hypothesis Structure & Rules
- Each hypothesis must have:
  - `hypothesis_id`: Unique string ID (e.g. "H_NAIVE_001")
  - `target_mode`: One of ["volatility_5d", "vol_regime_expansion", "direction_3d"]
  - `predicate`: A valid boolean expression using feature names, allowed operators, and allowed quantile thresholds (e.g., "delivery_pct > 0.60 AND fii_net_amt > 0.50")
  - `description`: Plain-English explanation of why this rule should hold.

## Response Format
Output a single valid JSON object with key "hypotheses" containing an array of 150 unique hypotheses.
Do NOT include any markdown formatting around JSON if possible, or wrap strictly in ```json ... ```.

Propose 150 diverse, high-conviction hypotheses across technical momentum, mean-reversion, volume/delivery accumulation, FII/DII institutional flows, market breadth, and VIX volatility regimes that you believe will hold in Indian large-cap daily market data.
```
